# FFTagger

Приложение для macOS на Go: локальная музыкальная библиотека, SQLite, FFmpeg и редактор тегов. Нативное окно AppKit с интерфейсом WKWebView, без Electron и внешних Go-модулей. Системная SQLite подключается через cgo.

## Запуск

Требуются macOS 13+, Go 1.23+, Xcode Command Line Tools и FFmpeg с ffprobe. Готовая сборка проверена на macOS 27.2 / Apple Silicon; работа на более старых версиях macOS отдельно не проверялась.

```sh
xcode-select --install  # если инструменты разработчика ещё не установлены
brew install go ffmpeg
make app
open build/FFTagger.app
```

Готовый пакет создаётся в `build/FFTagger.app`; его можно перенести в Applications. Сборка выполняется для архитектуры текущего Mac. Подпись локальная (ad hoc), без notarization для распространения на других компьютерах. FFmpeg должен быть установлен на том Mac, где запускается приложение. Проверяются PATH, `/opt/homebrew/bin`, `/usr/local/bin` и `Contents/Resources/bin` внутри пакета.

Для разработки: `make run`. Для запуска в браузере:

```sh
./build/fftagger -headless -db ./build/development.sqlite
```

Откройте адрес с токеном из терминала. В режиме браузера используйте «Указать путь вручную»: нативный выбор папки работает в `.app`. Параметры `-ffmpeg` и `-ffprobe` позволяют задать пути к утилитам, `-db` — расположение базы. По умолчанию сервер слушает только случайный порт loopback, проверяет Host, Origin и сессионный токен. Внешние сетевые подключения к интерфейсу не принимаются.

Сканирование выполняется параллельно: автоматически выбираются 2–8 работников по доступному числу процессоров Go. Каждый работник проверяет файл через ffprobe, извлекает обложку и передаёт данные в SQLite. Очередь ограничена; коллекция не загружается целиком в память. В прогрессе показано количество занятых работников и общий лимит; при наведении на текущий путь видны все активные файлы.

В боковой панели откройте «Настройки потоков»: доступны автоматический режим и ручной выбор 1–16 потоков. Значение сохраняется в SQLite и применяется к следующему сканированию или массовой записи тегов; уже работающий пул продолжает обработку с прежним лимитом. При массовой записи число работников не превышает число выбранных файлов. Прогресс показывает занятые потоки, активные файлы и результат каждого сохранения.

Также можно задать `-scan-workers` (1–16, 0 — автоматически), например:

```sh
open build/FFTagger.app --args -scan-workers 8
```

Явно переданный параметр обновляет сохранённую настройку при запуске нового процесса. Без параметра используется значение из БД. Из интерфейса настройку можно менять без перезапуска приложения. Запись в SQLite выполняет один работник за раз, одновременно с чтением тегов остальных файлов. При импорте в БД сохраняются только метаданные и обложки; аудио читается утилитами FFmpeg с исходного диска. Для медленного HDD или сетевой папки можно уменьшить число работников. Остановка отменяет активные процессы и ожидание записи, очищает очередь и дожидается завершения работников. Сканирование и редактирование одного файла используют общую блокировку; обработка других файлов продолжается.

## Возможности

- Нативный диалог выбора папки; параллельное рекурсивное сканирование, прогресс, остановка, список ошибок.
- Список источников в боковой панели хранится в SQLite. Выбранные через диалог или введённые вручную папки сохраняются автоматически; рядом с каждой — повторное сканирование, удаление из списка и время последнего запуска. Повторный выбор папки и её симлинка не создаёт дубликат. Удаление источника не удаляет треки и файлы. Недоступные диски остаются в списке до ручного удаления; при открытии приложения папки не сканируются автоматически. Папки, которые использовались до появления этой функции, нужно выбрать один раз заново.
- Проверка каждого обычного файла через ffprobe независимо от расширения, включая файлы без расширения. Скрытые файлы/папки, пакеты `.app`, симлинки, сама БД и резервные копии пропускаются. Список распознаваемых форматов определяется установленной сборкой FFmpeg.
- SQLite хранит путь, технические параметры, основные и исходные теги и обложку. **Аудиофайлы в БД не копируются.** Размер каталога зависит преимущественно от обложек.
- Повторное сканирование обновляет изменённые файлы и пропускает неизменённые. Удаление исходного файла вне приложения не удаляет запись каталога; её можно убрать кнопкой «Удалить трек…».
- Кнопка «Удалить трек…» в редакторе удаляет выбранный файл из папки и его запись, теги и обложку из SQLite. Требуется подтверждение в диалоге с названием и полным путём; «Отмена» и Escape сохраняют файл и несохранённые изменения редактора. Удаление выполняется без корзины, резервные копии предыдущих сохранений остаются. Доступно и для контейнеров, в которых нельзя редактировать теги. Если файл уже отсутствует, удаляется только запись библиотеки. При внешнем изменении файла нужно сначала пересканировать папку.
- Поиск подстроки по названию, исполнителю, альбому и пути. Отдельные фильтры по началу имени исполнителя и названия альбома, сортировка в обе стороны, страницы по 100 треков.
- Фильтр обложки: любая, отсутствует или есть. Раздел «Без обложек» включает этот фильтр; он сочетается с поиском, альбомом, исполнителем и сортировкой. После добавления обложки сохранённый трек исчезает из отфильтрованного списка.
- Раздел «Пропущенные» хранит в SQLite последние отчёты выбранных папок: путь, причину, подробности ошибки и время проверки. Доступны поиск по пути и фильтр причины. Повторное сканирование заменяет отчёт этой папки; при остановке остаётся частичный отчёт. Неизменённые импортированные треки не считаются пропущенными. Исключённые папки показаны одной строкой, без обхода содержимого; служебные файлы FFTagger не засоряют отчёт. Для папок, просканированных старой версией приложения, отчёт появится после повторного сканирования.
- Кнопка «Очистить БД…» в боковой панели удаляет каталог и отчёты после подтверждения, останавливает сканирование и освобождает место в файле SQLite. Музыка и резервные копии на диске, список источников, тема и настройка потоков сохраняются. Во время сохранения тегов очистка недоступна.
- Светлая, тёмная и системная темы. Выбор сохраняется в SQLite и применяется при следующем запуске, включая нативное оформление окна.
- Изменённые поля редактора выделяются обводкой в светлой и тёмной теме, в том числе при применении данных MusicBrainz. При наведении видно исходное значение. Обводка исчезает при возврате исходного значения, сбросе, сохранении или переходе к другому треку.
- Редактирование названия, исполнителя, альбома, исполнителя альбома, даты, жанра, номера трека/диска, композитора и комментария.
- Замена и удаление обложки; JPEG/PNG до 16 МиБ и 40 мегапикселей.
- После сохранения обложки или общих полей альбома приложение предлагает обновить другие треки того же исполнителя в том же альбоме. В диалоге можно выбрать поля (альбом, исполнитель альбома, дата, жанр, обложка) и отдельные треки; показаны прежние и новые значения. При переименовании альбома группа определяется по прежнему названию. Пустые исполнитель/альбом не объединяются в одну группу; сравнение выполняется по полным значениям без учёта регистра. Названия треков, исполнители треков, номера трека/диска, композиторы и комментарии массово не меняются.
- Изменения остальных файлов начинаются только после подтверждения. Для каждого используется обычная проверенная запись с резервной копией и обновлением SQLite. Видны прогресс и результат по каждому файлу, обработку можно остановить. Ошибка одного файла не отменяет уже сохранённые изменения и не мешает обработать остальные. Изменившиеся после показа предложения треки получают ошибку вместо перезаписи; неподдерживаемые форматы нельзя выбрать для недоступных им изменений.
- Поиск названия и исполнителя в MusicBrainz, выбор издания, получение обложки из Cover Art Archive. Результаты отмечены «Есть обложка», «Без обложки» или «Обложка: не удалось проверить». Издания с обложкой показаны первыми, внутри групп — по релевантности. Наличие проверяется HEAD-запросом без скачивания изображения: до четырёх проверок одновременно, одинаковые издания проверяются один раз, наличие и отсутствие обложки кешируются на 15 минут. Ошибка источника не считается отсутствием обложки. Закрытие поиска или новый запрос отменяют предыдущую проверку. Результат сначала попадает в редактор; запись в файл выполняется отдельным сохранением. Запросы отправляются только по команде пользователя. Аудиофайлы не отправляются в сеть.
- `⌘K` — поиск, `⌘S` — сохранить.

## Запись и сохранность файлов

| Контейнер | Теги | Обложка |
| --- | --- | --- |
| MP3, FLAC, M4A/MP4 с аудио, M4B, AIFF | Да | Да |
| Ogg Vorbis, Opus | Да | Да, FLAC picture block в Vorbis comments |
| WAV, WavPack, WMA/ASF | В пределах возможностей контейнера | Только чтение существующей |
| Остальные распознаваемые форматы; контейнеры с обычным видео | Чтение и импорт | Чтение |

Поддержка конкретного тега зависит от контейнера. Например, WAV не умеет сохранять все поля редактора. Если FFmpeg не сохранил запрошенный тег или обложку, приложение сообщает об этом и оставляет оригинал нетронутым. Неподдерживаемые контейнеры отображаются только для чтения.

При ошибках записи выполняются до **пяти повторов после первой попытки** (максимум шесть попыток), с паузой **одна секунда**. Повторяются создание и проверка временного файла, резервное копирование и замена исходника; успешная замена повторно не выполняется. Перед каждой попыткой заново проверяется исходный файл. Отмена, конфликт внешнего изменения, недопустимые теги и неуспешная проверка целостности прекращают обработку без повторов. Временные файлы неудачных попыток удаляются. Если после ошибки сетевой замены нельзя подтвердить состояние исходника, резервная копия сохраняется и автоматическая перезапись останавливается.

При сохранении:

1. Проверяются размер и время изменения исходника. Внешние изменения требуют повторного сканирования.
2. FFmpeg создаёт временный файл рядом с оригиналом, используя `-c copy`.
3. Через ffprobe проверяются теги, параметры аудио и обложка. SHA-256 всех аудиопотоков до и после записи должны совпасть.
4. Создаётся резервная ссылка на оригинал в `.fftagger-backups`. Если файловая система не поддерживает жёсткие ссылки (например, проверенный SMB-ресурс), оригинал копируется в резервный файл блоками с проверкой изменений и синхронизацией записи. Затем новый файл атомарно занимает исходный путь.
5. SQLite транзакционно получает новые теги, обложку и параметры файла. При ошибке БД исходный файл восстанавливается из резервной копии.

Резервные копии не удаляются автоматически. Их можно восстановить обычным копированием на исходный путь. При аварийном завершении между заменой файла и фиксацией SQLite повторное сканирование синхронизирует каталог с диском; оригинал остаётся в резервной папке. Атомарность файловой системы и транзакции SQLite не образуют единую транзакцию.

Удаление использует ту же блокировку файла, что сканирование и запись тегов. После проверки версии файл временно перемещается в отдельную скрытую папку `.fftagger-delete-*` рядом с ним. SQLite удаляет запись и связанный отчёт о пропуске транзакционно; только после успешной фиксации временный файл удаляется окончательно. Ошибка БД вызывает восстановление файла без перезаписи стороннего файла, если тот появился на исходном пути. Ошибки файловых операций повторяются до пяти раз с паузой в секунду. Если завершить очистку или восстановление не удалось, приложение сообщает путь оставшегося файла. При аварийном завершении процесса между этими шагами файл может остаться в `.fftagger-delete-*`; такие папки не сканируются и не удаляются автоматически. Идентификаторы удалённых треков повторно не используются.

Для сохранения нужны права на создание и замену файлов в папке трека. На сетевом ресурсе права папки проверяются сервером; отображаемые в Finder права могут отличаться от фактически разрешённых операций. При запрете записи приложение объясняет причину и не меняет оригинал. Резервное копирование на ресурсах без жёстких ссылок требует места для ещё одного оригинального файла.

FFmpeg перемультиплексирует контейнер: нестандартные поля, свойства файловой системы и расширенные атрибуты могут не перенестись. Оригинал сохраняется целиком. Приложение не переименовывает и не перемещает исходные аудиофайлы.

## База и индексы

По умолчанию: `~/Library/Application Support/FFTagger/library.sqlite`.

- `tracks`: отдельные колонки `artist`, `album`, `title`, нормализованные ключи, JSON остальных данных и BLOB обложки.
- **`idx_tracks_artist`** — отдельный индекс на `artist COLLATE NOCASE`.
- **`idx_tracks_album`** — отдельный индекс на `album COLLATE NOCASE`.
- `idx_tracks_artist_key` и `idx_tracks_album_key` — индексы нормализованных в Go Unicode-ключей для сортировки и префиксного поиска, включая кириллицу. SQLite `NOCASE` сам по себе складывает регистр только ASCII.
- `idx_tracks_title_key` — сортировка по названию.
- `idx_tracks_without_cover` — частичный индекс для треков без обложек.
- `sources` — сохранённые пути папок, время добавления и последнего запуска сканирования.
- `skipped_files` — последний результат пропуска каждого пути; `settings` — тема и число потоков, а также служебные настройки. Схема обновляется автоматически при открытии существующей базы.

При первом открытии базы старой версии таблица `audio_chunks` с аудиокопиями удаляется. Треки, теги, обложки, отчёты и настройки сохраняются; `VACUUM` и очистка WAL уменьшают файл БД. На большой базе первый запуск может занять время. Если освободить место сразу не удалось, приложение открывается с предупреждением в разделе «О библиотеке» и повторяет попытку при следующем запуске.

Общий поиск подстроки использует `instr`, поэтому B-tree его не ускоряет. Отдельные фильтры исполнителя и альбома используют индексируемые диапазоны; применение индексов проверяется через `EXPLAIN QUERY PLAN`. База работает в WAL, с отдельным соединением для чтения, чтобы импорт не блокировал просмотр уже сохранённых записей. Второй процесс с той же БД блокируется файловой блокировкой.

## Проверка

```sh
make test
make check  # go vet и go test -race
make bench  # сравнение 1 и 8 работников на 96 коротких FLAC с обложками
```

Интеграционные тесты создают короткие синтетические аудиофайлы. Проверяются девять контейнеров, теги с кириллицей и переводами строк, добавление/сохранение/удаление обложек, удаление тегов, идентичность аудиопотоков, резервные копии, конфликты внешних изменений, сканирование без расширения, отсутствие дубликатов, транзакционный откат, отсутствие аудио в БД, миграция старой базы с освобождением места, очистка каталога без удаления музыки и планы запросов SQLite. Без FFmpeg аудиотесты будут отмечены как пропущенные. Тесты MusicBrainz используют контролируемый HTTP transport и не зависят от внешней сети.

Проверяется сохранение потоков и источников после перезапуска и очистки каталога, независимое обновление темы и потоков, нормализация путей, дубликаты и недоступные папки.

Для предложений по альбому проверяются точная группа исполнителя/альбома, переименование альбома, подтверждение, выбор полей и треков, сохранение индивидуальных тегов, добавление/удаление и неизменность обложки, резервные копии, устаревшие предложения, частичные ошибки и отмена обработки.

Дополнительно проверяются пять повторов с секундными паузами, сохранение после временных ошибок FFmpeg, отсутствие повторного коммита и лишних резервных копий, остановка повторов при отмене/внешнем изменении, сбои HTTP и чтения ответа, сортировка по обложке, кеширование и ограничение параллельных проверок. Для массовой записи проверяются лимит работников, независимое сохранение при блокировке другого файла, неизменность лимита во время обработки и завершение всех работников при отмене.

Для удаления проверяются обязательное подтверждение, удаление файла и метаданных, неизменность предыдущих резервных копий, запрет устаревших подтверждений и симлинков, очистка уже отсутствующего файла, отказ в доступе, отмена ожидания блокировки, сканирование после удаления, восстановление при ошибке фиксации SQLite и защита от повторного использования ID. Тест ошибки фиксации БД использует системную утилиту `sqlite3`.

Для параллельного сканирования проверяются ограничение числа работников, отсутствие потери и дублирования файлов, остановка активных и ожидающих задач, повторный запуск после отмены, отмена ожидания SQLite и взаимное исключение сканирования/редактирования одного файла. Бенчмарк использует настоящие ffprobe/FFmpeg и новую SQLite для каждого прохода; подготовка файлов и открытие БД не входят в замер. Короткие файлы измеряют преимущественно чтение тегов и обложек, а не длительное чтение больших файлов с медленного диска.

Для отдельной проверки сохранения на доступном SMB-ресурсе: `FFTAGGER_TEST_SMB_ROOT=/Volumes/YourShare go test ./internal/library -run TestSaveOnNetworkVolume -v`. Тест создаёт собственную временную папку с синтетическим аудио, проверяет теги, обложку, резервную копию и SQLite, затем удаляет эту папку.

## Открытые источники

- [MusicBrainz API](https://musicbrainz.org/doc/MusicBrainz_API) и [поиск записей](https://musicbrainz.org/doc/MusicBrainz_API/Search).
- [Лимиты MusicBrainz](https://musicbrainz.org/doc/MusicBrainz_API/Rate_Limiting): запросы приложения разделены интервалом не менее 1,1 секунды; тайм-аут одной попытки — 25 секунд (проверка наличия обложки — 5 секунд). Сетевые сбои, обрывы чтения, HTTP 408/429/5xx повторяются до пяти раз с паузой в секунду; для MusicBrainz также сохраняется интервал не менее 1,1 секунды. Постоянные HTTP-ошибки, включая 404 «нет обложки», не повторяются.
- [Cover Art Archive API](https://musicbrainz.org/doc/Cover_Art_Archive/API): передняя обложка выбранного издания, до 500 px.
- [Документация FFmpeg](https://ffmpeg.org/ffmpeg.html): stream copy, метаданные, attached pictures.

Для распространяемой сборки задайте `-musicbrainz-agent 'FFTagger/0.1 (ваш URL или email)'`, чтобы User-Agent содержал реальный контакт сопровождающего. Сетевые ошибки и отсутствие обложки не мешают ручному редактированию. Акустический fingerprint-поиск и автоматическое массовое применение результатов не реализованы.
